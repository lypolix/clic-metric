# Clic-Metric Service

Clic-Metric — корпоративный сервис для сокращения ссылок с возможностью сбора кликов, контроля доступа, аудита событий и интеграции с корпоративным SSO через gRPC. Проект ориентирован для внутренних бизнес-процессов, автоматизации маркетинга и отслеживания эффективности рекламных/информационных кампаний.

## Возможности сервиса

- Сокращение ссылок (URL shortener) для корпоративных нужд
- Учёт и аналитика кликов по каждой ссылке
- Защита операций базовой HTTP-авторизацией
- Логирование действий и событий
- Гибкая интеграция с системами единой аутентификации (SSO) по gRPC
- Возможность доотправки событий через outbox-паттерн

## Польза для бизнеса

- Централизованное хранение сокращённых ссылок
- Прозрачные метрики эффективности 
- Снижение ручных ошибок и удобное управления ссылками
- Упрощённое администрирование пользователей и контроль прав через SSO
- Масштабируемость решения и интеграция в CI/CD пайплайны

## Техническая архитектура

### Основные технологии

- **Язык**: Go
- **Web Framework**: chi (HTTP сервер, middleware)
- **Хранилище**: PostgreSQL (через sql.DB)
- **SSO**: Интеграция gRPC с внешним Auth-сервером
- **Логирование**: slog для JSON и текстовых логов, в зависимости от среды
- **Тесты**: go test (unit-тесты на основные обработчики и утилиты)

### Архитектурные паттерны и подходы

| Паттерн           | Описание                                                                                       |
|-------------------|------------------------------------------------------------------------------------------------|
| Outbox            | Запись событий в отдельную таблицу Events для надёжной доставки внешним сервисам (event-sender)|
| Dependency Injection | Передача зависимостей (например, storage, logger, ssoClient) через конструкторы для unit-тестов|
| Retry/Resilience  | gRPC-клиент реализует повторные попытки запросов с таймаутами и логированием сетевых ошибок    |
| Middleware        | Использование middleware-цепочек для прозрачной авторизации и логирования                      |

## HTTP API: Таблица эндпоинтов

| Метод | Путь                    | Auth       | Описание                                  | Параметры/Тело запроса                      | Ответ                                    |
|-------|-------------------------|------------|-------------------------------------------|---------------------------------------------|------------------------------------------|
| POST  | /url                    | BasicAuth  | Сократить ссылку                          | `{"url": "https://..."}`                    | `{"alias": "..."} или error`             |
| GET   | /{alias}                | BasicAuth  | Перенаправление по alias                  | -                                           | HTTP 302 Location                        |
| GET   | /metrics/{alias}        | BasicAuth  | Получить число кликов для alias           | -                                           | `{"alias": "...", "clicks": 123}`        |

> Пример запроса:  
> ```
> curl -u myuser:mypassword -X POST http://localhost:8080/url \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/long-url-to-shorten"}'
> ```

## Интеграция с SSO gRPC сервером

Проект интегрирован с другим сервисом — [SSO gRPC Сервером Аутентификации и Авторизации](https://github.com/lypolix/sso-grpc):

- **gRPC-клиент внутри clic-metric** обеспечивает централизованную работу с пользователями: авторизация, проверка прав, аудит
- Используются методы: `Login`, `IsAdmin` и другие для проверки роли и доступа пользователя
- Реализованы повторы на сетевые ошибки и логирование входящих/исходящих запросов
- Конфигурация адреса и параметров клиента берётся из секции `clients.sso` в yaml-конфиге

> Пример инициализации SSO клиента
```
ssoClient, err := ssogrpc.New(ctx, log, cfg.Clients.SSO.Address, cfg.Clients.SSO.Timeout, cfg.Clients.SSO.RetriesCount)
```

## Примеры запуска и настройки

### Быстрый старт (локально):

1. Скопируйте `.env` или настройте `local.yaml`:
    ```
    env: local
    storagepath: "./storage.db"
    httpserver:
      address: "localhost:8080"
      ...
    clients:
      sso:
        address: "localhost:50051"
        timeout: 3s
        retriesCount: 2
    ```

2. Запустите миграции (создание таблиц будет выполнено автоматически при первом запуске).

3. Запуск сервиса:
    ```
    go run cmd/clic-metric/main.go
    ```

4. Для production настройте секреты и путь к базе в `prod.yaml`, запуск через systemd/unit или docker.
